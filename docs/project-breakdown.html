NeuroMem POC

A local, experimental AI-agent memory system inspired by useful properties of human memory. Tests whether structured, consolidating, associative memory beats conventional vector RAG.

Python 3.12 FastAPI LangGraph OpenSearch k-NN Streamlit OpenAI gpt-4o / text-embedding-3-large Phase 0 → 7 delivered

The research question

Can an agent with structured, consolidating, associative, decaying memory behave more effectively than an agent using conventional vector RAG alone?

Conventional RAG treats every retrieval as a fresh cosine-similarity lookup. NeuroMem layers importance, recency, activation (retrieval-reinforced, decayed with time), relationships, and keyword signals on top of the same semantic base — and consolidates raw episodic memories into durable semantic and procedural facts, always preserving provenance and never overwriting conflicts.

Delivered phases

  1. 0
    Bootstrap. Repo, config, structured logging, adapters (LLM + embeddings), health endpoints, contract-visible 501 stubs.
  2. 1
    Storage. CRUD, relationships, ULID-prefixed IDs routed to correct indexes, idempotent bootstrap.
  3. 2
    Retrieval. Hybrid semantic (k-NN) + keyword (BM25) + one-hop relationship expansion, 6-signal weighted rank, mandatory Explanation object.
  4. 3
    Agent. 7-node LangGraph on OpenAI: classify → recall → plan → tools → evaluate → answer → candidate extraction.
  5. 4
    Consolidation. Async worker + LLM conflict adjudication. Turns become episodic sources; candidates become derived memories with DERIVED_FROM / SUPERSEDES / CONTRADICTS edges. Never overwrites.
  6. 5
    Lifecycle. Retrieval-time strengthening (bulk painless script), query-time decay, /access + /decay + /{id}/history. No deletes.
  7. 6
    Evaluation. YAML scenario harness, Mode A (naive RAG) vs Mode B (NeuroMem) with identical LLM prompts, markdown report with per-mode metrics.
  8. 7
    Dashboard. Streamlit UI with six real tabs backed by four new endpoints and a pyvis relationship graph.

Ranking model

Baseline weights from plan §10; fully configurable per-query or via Settings.

Signal Weight Source
semantic0.40OpenSearch k-NN cosine, already in [0, 1]
keyword0.15BM25 multi_match normalised by max in the result set
importance0.20Author-supplied 0–1
recency0.10exp(-λ_recency · age_days_since_created)
activation0.10activation · exp(-λ_activation · age_days_since_last_access)
relationship0.05One-hop boost when both endpoints are in the candidate set

Load-bearing design decisions

  1. Never overwrite a memory. Conflicting facts get SUPERSEDES or CONTRADICTS edges; the old row stays queryable. Decay is query-time only — no writes, no deletes.
  2. ULID-prefixed IDs (epi_ / sem_ / pro_ / rel_) route to the correct index as a pure string function. No lookup roundtrip.
  3. extra=forbid on every Pydantic model mirrors OpenSearch's dynamic: strict mapping. Schema drift fails fast on both sides.
  4. Discriminated union for Memory on memory_type. One POST /memory/store handler serves all three types; TypeAdapter dispatches on read.
  5. Explanation is a first-class field, not a debug hint. Retrieval Trace tab renders per-signal contributions directly from it.
  6. Bulk painless _bulk script for strengthening: one round-trip bumps activation + access_count + last_accessed_at atomically per doc.
  7. Two-model LLM adapter, one client: gpt-4o-mini for extraction and classification (JSON mode, temp=0), gpt-4o for the answer node and conflict adjudication.
  8. Route ordering matters in FastAPI — literal /memory/stats and friends declared before /memory/{memory_id} to avoid the wildcard swallowing them.
  9. Evaluation isolation via per-run {run_id} markers in seeded memory content, not deletes. Runs coexist forever; report includes the run IDs.
  10. The agent depends on MemoryService, not MemoryStore. Storage can be swapped without touching the graph, and consolidation reuses the same facade the routes see.

Explicitly out of scope

  • Learned or reinforcement-tuned ranking weights.
  • Cross-encoder reranking.
  • Multi-hop relationship traversal beyond depth 3.
  • LLM-as-judge scoring in evaluation (substring matching only).
  • Additional distributed workers or Kafka / Redis beyond the RabbitMQ worker.
  • Automatic deletion of decayed / superseded memories.
  • Multi-tenant memory scoping (single global pool, agent_id is provenance only).
  • Local LLM inference (POC uses OpenAI end-to-end).
